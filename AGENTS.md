# Пользовательские обновления

После каждой завершённой доработки, меняющей поведение или интерфейс платформы,
добавляйте понятное пользователю описание в `services/release_catalog.py`.
Это постоянное требование владельца проекта: изменения должны появляться в окне
«Что нового» после переноса кода на сервер.

- Одна законченная задача — одна запись с новым уникальным идентификатором релиза.
- Кратко описывайте результат для пользователя, без секретов, служебных путей и сырых сообщений коммитов.
- У каждого изменения указывайте соответствующий модуль, чтобы сервер отфильтровал текст по правам аккаунта. Общие изменения помечайте как общие только если они действительно касаются всех.
- При выпуске новой версии продукта удаляйте из каталога описания прошлых версий: в «Что нового» должны оставаться только изменения текущей версии. Это требование владельца от 20.10.2026.
- Для нового уведомления используйте новый уникальный идентификатор; не переиспользуйте идентификатор уже прочитанного выпуска.
- Не включайте рабочие JSON, базы данных, пароли и отметки о прочтении в Git. Правила `.gitignore` для них сохраняются.
- Перенос кода через GitHub не означает разрешение на деплой: запуск и обновление рабочего сервера — только по отдельной команде.

Формат записи и порядок выпуска: `docs/release-notes.md`.
