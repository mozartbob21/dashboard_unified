# Обновление остатков ЗИП из папки А

Кнопка «Обновить данные (из папки А)» получает полный список файлов настроенного
источника и обновляет локальную очередь куратора. Согласование и
публикация в ЗИП остаются отдельными действиями.

## Облако МО

1. В разделе «Пользователи → Логины и пароли» выбрать
   «Облако МО — ЗиП · cloud.mosreg.ru».
2. Ввести логин и пароль облака. Ссылка на папку уже заполнена:
   `https://cloud.mosreg.ru/apps/files/?dir=/&fileid=10968596`.
3. Сохранить доступ и нажать «Проверить доступ к папке». Эта проверка читает
   список Excel-файлов, но не загружает остатки и не согласовывает РСО.
4. В кураторе ЗиП проверить подпись «Источник: Облако МО» и обновить данные.

После сохранения этого доступа источник выбирается сервером: старые открытые
вкладки с Яндекс Диском не переопределяют его. Пока доступ к облаку не сохранён,
используется `ZIP_FOLDER_A_URL` или прежняя публичная папка Яндекс Диска.
При ошибке облака скрытого переключения на другой источник нет.

Подключение использует HTTPS/WebDAV ownCloud без браузерного кликера. Папка
определяется по её `fileid`, затем проверяется её идентификатор. Если облако
не позволяет определить путь, в дополнительных настройках можно указать путь
папки внутри аккаунта; он также обязан соответствовать `fileid` ссылки.
Сканирования корня аккаунта вместо указанной папки нет. Подпапки выбранной
папки обходятся с ограничениями глубины, числа записей и времени.

Если у облака включена двухфакторная защита, может потребоваться пароль
приложения, выданный самим облаком. Серверу Нейроны нужен сетевой доступ к
`cloud.mosreg.ru` и доверенная цепочка сертификатов. Проверка TLS не отключается.

Пароль хранится зашифрованным в существующей таблице `integration_credentials`;
ключ `data/auth/integrations.key` нужно сохранять вместе с резервной копией БД.
Настройка и проверка доступа доступны только управляющим пользователями.
В интерфейс куратора пароль, логин и приватные ссылки скачивания не передаются.

## Даты файлов

В очереди и согласованных остатках показывается дата из метаданных источника:
«Создан в источнике», если источник сообщает создание, иначе
«Изменён в источнике». Дата изменения не выдаётся за создание или первое
появление файла. Если источник не сообщает обе даты, выводится
«Дата источника неизвестна». Для ручной загрузки источник также неизвестен.

Время загрузки в Нейрону сохраняется для диагностики, но больше не является
основной датой карточки. Существующие метаданные из манифеста подхватываются
без повторной классификации и без потери ручных правок; для остальных файлов
даты появятся при следующем успешном обновлении источника. Старое локальное
время изменения файла не используется как дата его создания в облаке.

## Обработка сбоев

- Временные ошибки сети и HTTP 408/429/5xx повторяются до трёх раз. При повторном
  скачивании с Яндекс Диска запрашивается новая ссылка. Бюджет обновления —
  четыре минуты, проверяется между запросами и полученными блоками ответа;
  оставшиеся файлы помечаются ошибками. Это не жёсткий общий таймер:
  сетевой таймаут Requests ограничивает отсутствие данных, поэтому медленно
  поступающий ответ может увеличить общее время обновления.
- Перед заменой локального файла проверяются размер, MD5 (если он указан
  источником), целостность XLSX и чтение листа. Лимиты: 50 МБ на файл,
  100 МБ распакованного содержимого. Старый бинарный XLS не поддерживается
  серверным импортом; его нужно сохранить как XLSX.
- Ошибка отдельного файла не останавливает другие загрузки. Исправная старая
  копия сохраняется со старой контрольной суммой и датой; следующий запуск снова
  попробует получить новую. Неудачная загрузка не переимпортирует старую копию
  поверх правок куратора.
- При частичном обновлении локальные файлы не удаляются. Некорректный или
  неполный список папки прерывает синхронизацию до изменения файлов.
- Повторный параллельный запуск блокируется и в интерфейсе, и на сервере
  (включая несколько процессов Windows). Блокировка освобождается при завершении
  процесса; файл `folder_a.lock` вручную удалять не требуется.
- Итог и список проблемных файлов остаются под кнопками. Временные подписанные
  ссылки скачивания и технические исключения в браузер не отправляются.

Список синхронизации и последние ошибки: `data/zip_curator/folder_a_manifest.json`.
В нём нет временных ссылок скачивания. Кэш находится в
`ZIP_INPUT_DIR/folder_a` (по умолчанию `data/zip_curator/input/folder_a`).

## Ошибка Яндекс Диска 13.10.2026

На независимой проверке в отдельной временной папке загрузились 22 из 35 Excel-файлов;
13 стабильно возвращали HTTP 500. Для проверенного проблемного файла Яндекс Диск
вернул `file IO failure: no successful lookup result` как по исходной ссылке,
так и по заново полученной. Запрос архива всей папки также вернул HTTP 500.
Это отказ чтения файла на стороне источника; смена логина Нейроны его не устраняет.

Если повторное обновление не помогает, владелец исходников должен проверить
проблемные файлы на Яндекс Диске и повторно загрузить их из исправных оригиналов.
Не удаляйте единственную копию. Как временный вариант, исходные XLSX можно
загрузить кнопкой «Загрузить файлы вручную» в кураторе.

## Установка на рабочем сервере

1. Получить обновлённый код через GitHub.
2. Перезапустить процесс Нейроны и обновить страницу куратора в браузере.
3. Нажать «Обновить данные (из папки А)» и посмотреть результат под кнопками.

Новые пакеты и переменные `.env` не нужны. Обновление не меняет правила
согласования РСО и не удаляет опубликованные остатки.

## Постоянный справочник классификации

«Загрузить справочник» сохраняет XLSX на сервере как дополнения и изменения в
`data/zip_curator/dictionary.json`. Совпадающие наименования обновляются, остальные
записи сохраняются. Новые категории и группы становятся доступны при ручной правке.
Файл данных не включён в Git: обновление кода не заменяет его базовым справочником.

Страница при открытии получает справочник с сервера. «Скачать справочник» также
сначала получает его актуальную серверную версию. Справочник общий для пользователей
модуля; он используется сервером при последующей классификации импортируемых остатков.

Формат: XLSX, первая строка — «Наименование (норм.)» (или «Наименование»),
«Категория», «Группа»; необязательная колонка «Вода». Порядок колонок может меняться.
В «Вода» допустимы «да»/«нет», 1/0, true/false, yes/no, +/- или пустая ячейка.
При ошибке в файле прежний справочник остаётся целиком. Ограничения: 10 МБ,
50 000 строк. Успешное сохранение подтверждается только после записи на сервере.

После установки исправления нужно один раз повторно загрузить свой справочник:
старый обработчик держал его только в памяти страницы и не записывал на сервер.
Согласованные остатки и текущие правки очереди при загрузке справочника не меняются.
