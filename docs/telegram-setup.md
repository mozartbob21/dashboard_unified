# Telegram в «Нейроне»

Модуль работает на том же компьютере, что и локальный сервер «Нейроны».
Браузеры сотрудников обращаются только к «Нейроне»; к Telegram подключается сервер через MTProto.
VPN на рабочем компьютере сотрудника не требуется, если сервер имеет доступ к Telegram напрямую или через настроенный прокси.
Сам Telegram API не обходит сетевую блокировку сервера.

## Установка на сервере

1. Обновите проект целиком, включая новые `services/telegram/`, `routers/telegram.py`,
   `templates/telegram.html`, `static/telegram.js`, `static/telegram.css`,
   изменения `app.py`, `core/roles.py`, `templates/home.html`, `requirements.txt`.
2. Установите зависимости в окружение, из которого запускается «Нейрона»:

   ```sh
   python -m pip install -r requirements.txt
   ```

3. Зарегистрируйте приложение в [Telegram API development tools](https://my.telegram.org/apps).
   Нужны `api_id` и `api_hash` приложения, а не токен бота.
   Порядок выдачи ключей: [официальная документация Telegram](https://core.telegram.org/api/obtaining_api_id).
4. Добавьте в существующий `.env` сервера параметры из `docs/telegram.env.example`.
   `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` общие для приложения; каждый пользователь входит
   в собственный Telegram-аккаунт. Не вводите ключи приложения в чат с помощником.
5. Перезапустите сервер. В управлении пользователями назначьте нужным сотрудникам блок
   **«Telegram — выбранные чаты»**. Для Keycloak предусмотрена роль `telegram`.
   Новые права не выдаются существующим пользователям автоматически.
6. На главной странице появится карточка Telegram. Каждый сотрудник подключает свой номер,
   вводит код Telegram и, если потребуется, пароль двухэтапной защиты.
7. Через «Выбрать чаты» отметьте нужные диалоги и сохраните выбор.

В локальной сети для передачи кодов, паролей и переписки используйте HTTPS на сервере «Нейроны».

## Если Telegram недоступен с сервера

Задайте `TELEGRAM_PROXY_URL`, например `socks5://127.0.0.1:1080`, либо адрес
доступного SOCKS5/SOCKS4/HTTP-прокси. Для пароля или логина со спецсимволами используйте URL-кодирование.
Прокси используется только серверным Telegram-клиентом; настройки браузеров сотрудников не меняются.
Поддержка MTProxy в этой версии не реализована.

## Сессии и данные

Сессии, выбранные чаты, временный этап входа и идентификаторы отправки хранятся зашифрованными
в `.private/telegram/sessions.sqlite`. Ключ `.private/telegram/session.key` создаётся автоматически.
Этот каталог не раздаётся через `/data` или `/static`, исключён из Git и привязан к компьютеру-серверу.
При переносе приложения сохраните базу и ключ вместе в защищённой резервной копии.
Если используется переменная `TELEGRAM_SESSION_KEY`, сохраните её вместо файла ключа.
Не удаляйте ключ при обновлении: без него нельзя расшифровать существующие подключения.

Каждая запись принадлежит неизменяемому идентификатору пользователя «Нейроны»;
передать другой идентификатор через API нельзя. Даже администратор видит только свой Telegram.
Отключённый пользователь «Нейроны» теряет доступ к модулю. Сессию можно отозвать в самом Telegram
через «Настройки → Устройства → Neurona Web»; повторное подключение потребуется в «Нейроне».

Код подтверждения и пароль 2FA не сохраняются. История сообщений не копируется в локальную базу.
Повтор запроса отправки с тем же `request_id` использует тот же Telegram `random_id`.
Список чатов и текущая переписка запрашиваются от имени подключённого пользователя;
читать/отправлять/скачивать файлы через API можно только в выбранных чатах.

## Возможности текущей версии

- Личные чаты, группы и каналы; выбор до 100 чатов, список загружается порциями по 50.
- Чтение последних сообщений, подгрузка истории и обновление каждые 15 секунд на открытой вкладке.
- Текстовые сообщения и ответы на сообщения. Отправка выполняется только по действию пользователя.
- Скачивание входящих фото и файлов до 20 МБ через сервер «Нейроны».
- Собственные черновики в памяти открытой страницы, без хранения в браузере между входами.
- Отзыв текущей Telegram-сессии кнопкой «Отключить аккаунт».

Звонки, секретные чаты, отправка файлов, реакции, редактирование/удаление сообщений,
создание чатов и полнотекстовый поиск по всей переписке в эту версию не входят.
Права Telegram сохраняются: например, участник канала без права публикации не сможет отправлять сообщения.
Если Telegram ограничивает частоту запросов, интерфейс показывает время ожидания.

## Проверка

```sh
python -m unittest test.test_telegram -v
```

Тесты используют временные базы и подменённые Telegram-соединения: они не подключают реальные аккаунты
и не отправляют сообщения. Для проверки живого подключения нужны ваши ключи приложения,
доступ сервера к Telegram и вход пользователя через интерфейс.

Реализация использует [Telethon 1.x](https://docs.telethon.dev/en/stable/basic/signing-in.html)
и [зашифрованные StringSession](https://docs.telethon.dev/en/stable/concepts/sessions.html).
