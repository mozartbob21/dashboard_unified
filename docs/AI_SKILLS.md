# Навыки ИИ в чате Нейроны

Навык — установленная администратором папка с `SKILL.md`: описанием задачи и инструкциями для её выполнения. Чат сначала выбирает подходящие навыки по описаниям, затем читает инструкции выбранных навыков. Справочные материалы загружаются по запросу. ИИ-команда задаёт профессиональные точки зрения, а навык — порядок работы и доступные инструменты. Оба механизма работают с существующей Qwen; это не независимые агенты с отдельными учётными записями.

На этом компьютере выполняются разработка и имитационные проверки. Рабочая Qwen и её ключи настроены на сервере. Здесь не нужны ключи, вызовы Qwen, обращения к порталам или новые внешние сервисы. На сервере подбор навыков, выбор инструментов и итоговый ответ используют существующий адаптер Qwen. Навыки не добавляют новых внешних направлений передачи данных.

## Семь установленных навыков

| Название | Идентификатор | Когда полезен | Разрешённые инструменты |
|---|---|---|---|
| Расчёты | `calculations` | Арифметика, проценты, проверка расчёта и единиц | `calculate` |
| Анализ таблиц | `table-analysis` | Структура таблицы, пропуски, числовые итоги и проверяемые выводы | `table_profile`, `attachment_text` |
| Разбор документов | `document-analysis` | Требования, исполнители, сроки и противоречия в приложенных документах | `attachment_text`, `read_resource` |
| Деловые тексты | `business-writing` | Проекты писем, записок, поручений и докладов | `read_resource` |
| Отчёт по платформе | `platform-report` | Отчёт из разрешённых пользователю сохранённых сводок модулей | `platform_report`, `read_resource` |
| Ответ на обращение | `appeal-response` | Проект предметного ответа жителю с проверкой фактов и обещаний | `attachment_text`, `read_resource` |
| Оперативная сводка | `operational-brief` | Сводка ЖКХ из предоставленной переписки или документа | `attachment_text`, `read_resource` |

Последние два навыка учитывают рабочие процессы проекта. В `services/appeals/storage.py` сбор фактов, проверка, утверждение и отправка являются разными этапами. Навык готовит проект текста и не меняет статус обращения. Структура оперативной сводки опирается на `services/summarizer/engine.py`: время, событие, ресурс, место, причина, затронутые объекты, охват, бригада, сроки и информирование. Плановый срок отделяется от фактического, отсутствие сведений обозначается явно. Как и в `services/edds/report_snapshot.py`, неизвестный охват жителей не превращается в ноль. Большие системные промпты модулей в пакеты не копируются.

## Как обрабатывается сообщение

1. Сервер проверяет сообщение и вложения, определяет текущую учётную запись и её права. Режим `auto` включает подбор навыков, `off` сохраняет прежний путь обработки чата.
2. В режиме `auto` подбор видит только описания включённых навыков, вопрос, короткую подсказку из предыдущего вопроса и имена с типами текущих вложений. Полные инструкции и содержимое файлов на этом этапе не передаются. Явное упоминание, например `$calculations`, выбирает доступный включённый навык без вызова автоматического подбора.
3. Для выбранных навыков загружаются тела `SKILL.md`. Модель один раз предлагает ограниченный список действий. Сервер проверяет имена инструментов, параметры и разрешения и выполняет действия последовательно. Дополнительного цикла самостоятельного планирования нет.
4. Итоговый ответ получает инструкции выбранных навыков, проверенные результаты инструментов, предупреждения и разрешённый контекст платформы. Если выбран навык, вложения попадают в этот контекст через реально выполненные инструменты. Непрочитанные файлы отмечаются. Если навыки не выбраны, обычный ответ может использовать сокращённые извлечённые тексты вложений.
5. В интерфейс поступают события о действиях и один итоговый ответ. Ошибка подбора или отдельного инструмента не выдаётся за успешную проверку: чат продолжает работу с предупреждением и доступными результатами. Недоступность самой Qwen возвращает обычное сообщение об ошибке ИИ.

Подбор и планирование используют максимум первые 12 000 символов текущего вопроса и 1 200 символов предыдущего. Полная история в эти служебные вызовы не отправляется. Итоговый ответ использует существующий механизм истории чата. Вложения доступны инструментам только в текущем сообщении; файл из прошлого сообщения нельзя повторно открыть по имени.

Режим `off` отключает именно навыки. Существующий выбор ИИ-команды, чтение вложений и механизм отчётов платформы продолжают работать. Старый клиент, который не передаёт `skills_mode`, получает режим `off`. Отсутствие новых полей в сохранённом JSON диалога не требует миграции.

## Доступ к данным и персональные настройки

Маршруты чата требуют действующую сессию. Отдельного права администратора для включения собственного навыка нет. Пользователь включает и выключает уже установленные навыки только для своей учётной записи; наборы устанавливает администратор в серверный каталог.

Настройки сохраняются в SQLite-таблице `skill_preferences` с ключом `(account_key, skill_id)`. Локальная учётная запись и Keycloak имеют разные ключи. Отсутствие записи означает, что корректно установленный навык включён. Если пакет временно удалён и затем возвращён с тем же идентификатором, сохранённое выключенное состояние остаётся. Эти настройки персональны; существующее JSON-хранилище диалогов отдельной изоляции по владельцам в рамках этой функции не получает.

Инструмент «Данные платформы» читает сохранённые сводки через существующий `report_context`. Исходный вопрос, выбранный источник и результат `effective_modules(user)` привязаны к запросу на сервере. Модель не передаёт собственные права, список модулей или другой вопрос в этот инструмент. Наличие навыка «Отчёт по платформе» не открывает закрытый модуль и не запускает обновление портала.

Поле `include_context=false` запрещает чтение данных платформы для запроса, в том числе из навыка. Значение `true` явно запрашивает выбранные данные независимо от автоматического выбора навыка; они читаются один раз и повторно используются в том же запросе. Если поле не задано, в режиме `auto` чтение может запросить разрешённый инструмент, а в режиме `off` действует прежний механизм определения отчётного запроса. Неоднозначная выборка возвращает уточняющий вопрос.

Успешно определённая выборка сохраняется у сообщения пользователя как `report_scope`. Следующий вопрос может продолжить её, но доступ снова проверяется по текущим правам. Сохраняются одиночные поля `module`, `source`, `municipality`, списки `modules`, `sources`, `municipalities` и поддерживаемая группировка `group_by=municipality`. Старые сообщения без этих полей остаются читаемыми.

## HTTP API

| Запрос | Назначение и ответ |
|---|---|
| `GET /aichat/api/skills` | Каталог текущего пользователя: `items`, безопасные сообщения `issues`, `scope: "account"`. Ответ не кешируется. |
| `PATCH /aichat/api/skills/{skill_id}` | Строго `{"enabled": true}` или `{"enabled": false}`. Возвращает обновлённый каталог. Лишние поля и неверные типы — `400`, отсутствующий или повреждённый навык — `404`. |
| `GET /aichat/api/report-options` | Доступные текущему пользователю варианты источников и модулей для отчёта. |
| `POST /aichat/api/send` | Сообщение `multipart/form-data`; обычный JSON или поток событий по заголовку `Accept`. |

Элемент каталога содержит `id`, `name`, русское `title`, `description`, `allowed_tools`, `metadata`, `enabled`, `unsupported_tools`. Полный текст `SKILL.md` и справочники в каталог не включаются. В `allowed_tools` персонального каталога остаются только зарегистрированные на сервере инструменты. Неизвестные декларации вынесены в `unsupported_tools` и `issues`; они не становятся исполняемыми.

Основные поля отправки сообщения:

| Поле | Значение |
|---|---|
| `text` | Текст до 40 000 символов. Требуется текст или хотя бы одно вложение. |
| `dialog_id` | Идентификатор существующего диалога; без него создаётся новый. Переданный отсутствующий диалог — `404`. |
| `skills_mode` | `auto` или `off`; без поля — `off` для совместимости. |
| `team` | Необязательная JSON-строка существующего формата ИИ-команды, до 4 096 символов. Без поля сохраняется состав диалога. |
| `file` | Повторяющееся поле текущих вложений. Имена должны различаться после очистки имени и ограничения до 240 символов. |
| `include_context` | Строка `true` или `false` для явного выбора данных платформы; можно не передавать. |
| `context_module`, `context_source`, `context_municipality` | Выбор данных платформы, каждое поле до 240 символов. Значения не заменяют проверку прав. |

Без `Accept: application/x-ndjson` ответ остаётся единым JSON. В нём есть `dialog_id`, `answer`, `ok`, `response_kind`, `team`; дополнительные поля — `skill_run`, `report_scope`, `report_sources`, `error_code`, `request_id`. `response_kind` принимает `answer`, `clarification` или `error`. Ошибки входных параметров возвращаются до запуска обработки и записи диалога. У неавторизованного клиента GET перенаправляется на вход, изменение настроек или отправка сообщения возвращает `401`; запрос изменения с чужого сайта — `403`.

### Поток действий

При `Accept: application/x-ndjson` сервер возвращает строки JSON с `Content-Type: application/x-ndjson`, `Cache-Control: private, no-store` и `X-Accel-Buffering: no`. Это поток событий выполнения, а не поток отдельных токенов ответа.

```json
{"type":"step","id":"skill-routing","kind":"routing","label":"Подбор навыков","status":"running"}
{"type":"step","id":"skill-routing","kind":"routing","label":"Навыки выбраны","status":"done"}
{"type":"ping"}
{"type":"result","dialog_id":"example1","answer":"Результат: 100.","ok":true,"response_kind":"answer","team":null}
```

`step` содержит `id`, `kind`, русскую `label`, `status` и необязательный `skill_id`. Повторный `id` обновляет тот же шаг. Виды: `routing`, `skill`, `tool`, `model`, `attachment`; состояния: `running`, `done`, `error`. При отсутствии событий около 15 секунд приходит `ping`. Событие `result` завершает поток и содержит обычный результат отправки сообщения. Пример сокращён: реальный ответ режима `auto` также содержит `skill_run`.

Клиент должен собирать строки через границы сетевых фрагментов, пропускать `ping` и считать запрос завершённым только после `result`. HTTP `200` у уже открытого потока не означает успешный ответ: проверяется `ok` в `result`. После разрыва соединения следует обновить историю перед повторной отправкой. Сервер сохраняет уже принятое сообщение пользователя при отмене обработки; прерванный ответ не выдаётся за завершённый.

## История и открытая информация о действиях

В сообщение ассистента добавляется необязательное `skill_run`: выбранные навыки, инструменты с итоговым статусом, последние состояния шагов и предупреждения. Ограничения: 2 навыка, 4 инструмента, 40 разных шагов, 8 предупреждений по 300 символов. Подпись шага ограничена 180 символами.

Эта запись показывает выполненные действия, а не скрытые рассуждения модели. В неё не сохраняются полные инструкции, аргументы инструментов и необработанные результаты чтения файлов. Текст вопроса и итогового ответа по-прежнему сохраняется как обычная переписка. Инструкции выбранных навыков и результаты инструментов передаются в текущий модельный запрос отдельно от пользовательского текста. Вложения и справочники обозначены как данные, а содержащиеся в них команды не дают новых прав.

Диалоги сохраняются существующим JSON-хранилищем: изменения сериализуются блокировкой внутри процесса, файл заменяется атомарно. Старые сообщения без `skill_run`, `response_kind` или `report_scope` остаются совместимыми.

## Зарегистрированные инструменты и лимиты

| Название | Идентификатор | Граница выполнения |
|---|---|---|
| Вычисление | `calculate` | Десятичная арифметика `+ - * / %`, скобки и унарные знаки; выражение до 512 символов. Функции, степени, `eval` и выполнение кода недоступны. |
| Анализ таблицы | `table_profile` | Только текущие CSV/XLSX, до 500 строк данных и 32 столбцов. Первая строка — заголовок. Формулы не вычисляются; сокращение данных отмечается. |
| Чтение вложения | `attachment_text` | Только точное имя вложения текущего сообщения, до 8 000 символов извлечённого текста. Неуспешное извлечение не считается прочитанным файлом. |
| Чтение справки навыка | `read_resource` | Только текст в `references/` активного навыка, до 8 000 символов в результате инструмента. |
| Данные платформы | `platform_report` | Без параметров модели; сохранённые данные по исходному запросу и серверным правам, без обновления внешних источников. |

За сообщение выбирается до 2 навыков и планируется до 4 действий. Одинаковые повторные действия пропускаются. Общий объём инструкций для модели — до 16 000 символов, результатов с предупреждениями — до 20 000 символов. Сокращения отражаются в предупреждениях. Подбор использует один вызов Qwen с лимитом 400 токенов и ожиданием до 45 секунд, планирование — один вызов с лимитом 1 600 токенов и ожиданием до 90 секунд; явный выбор навыка не требует первого вызова.

Запрос принимает до 8 файлов, по 8 МиБ каждый, суммарно до 24 МиБ; предварительный предел всего HTTP-тела с multipart-разметкой — 25 МиБ. Разбор формы ограничен 20 обычными полями. Из каждого поддерживаемого документа извлекается до 60 000 символов. Для изображений требуется распознанный текст, для аудио — расшифровка: инструменты навыков сами не запускают распознавание.

Архивные форматы при общем извлечении ограничены 2 000 элементами и 64 МиБ распакованного объёма: перед извлечением содержимое проверяется порциями по 64 КиБ. XML-объявления DTD и ENTITY отклоняются также в UTF-16/UTF-32. Анализ таблиц имеет дополнительные границы: CSV до 2 МиБ; XLSX — до 1 000 элементов, 24 МиБ распакованного объёма и 8 МиБ на элемент. Внешние связи книги и опасные XML-объявления отклоняются. Ограниченный фрагмент нельзя представлять как проверку всего большого документа или полной таблицы.

`allowed-tools` в `SKILL.md` запрашивает существующие инструменты, но не создаёт их. Сервер повторно пересекает разрешения навыка с `services/aichat/skills/tools.py::SPECS` и проверяет параметры перед выполнением. Запись `Bash`, имя сетевого клиента или путь к скрипту не дают возможности их запустить. Для нового инструмента разработчик отдельно реализует серверный обработчик, регистрирует описание, ограничивает входы и выходы, проверяет доступ и добавляет отрицательные тесты. Добавления одного имени в описание недостаточно.

## Установка своего навыка

Администратор добавляет обычную папку в `skills/aichat/<name>/` на сервере. Через персональный переключатель нельзя загружать или заменять серверные пакеты.

```text
skills/aichat/meeting-notes/
  SKILL.md
  references/
    format.md
```

Пример `SKILL.md`:

```markdown
---
name: meeting-notes
description: "Извлекает из предоставленного протокола решения, исполнителей и сроки. Используйте для подготовки перечня поручений после совещания."
metadata:
  neurona-title: "Поручения совещания"
  version: "1.0"
allowed-tools: attachment_text read_resource
---

Прочитай относящийся к задаче документ через attachment_text.
Отдели принятые решения от предложений. Отсутствующие сроки и исполнителей
пометь явно. При необходимости прочитай references/format.md через read_resource.
Подготовь проект перечня поручений в ответе чата.
Не создавай поручения в системах и не отправляй уведомления.
```

Формат Agent Skills требует `name` и `description`; поддерживаются `license`, `compatibility`, `metadata`, `allowed-tools`. Имя: 1–64 символа `a-z`, `0-9`, `-`, без двойных и крайних дефисов, совпадает с каталогом. Описание — непустая строка до 1 024 символов, `compatibility` — до 500. `metadata` — до 32 пар строковых ключей и значений; `metadata.neurona-title` задаёт русское отображаемое имя до 120 символов. Если название не задано или не содержит кириллицы, интерфейс показывает «Дополнительный навык». Версии и числа в метаданных пишутся строками. `allowed-tools` — строка имён через пробел, до 32 имён по 128 символов. Повторяющиеся YAML-ключи, ссылки и якоря YAML и произвольные теги не поддерживаются.

При следующем обращении к каталогу новые папки и изменения видны без перезапуска приложения. Открытое окно интерфейса может потребовать обновления каталога. Для замены пакета сначала подготовьте полный корректный набор, затем замените его целиком, чтобы запрос не прочитал промежуточное содержимое.

Загрузчик проверяет не более 64 записей корневой папки; при превышении сообщает, что часть наборов не загружена. Корневую папку следует использовать только для навыков. Каталог читает только YAML-заголовок до 32 КиБ. Тело выбранного навыка читается отдельно и ограничено 64 КиБ; текстовый ресурс — также 64 КиБ. Ресурсы доступны только как UTF-8 `.md`, `.txt`, `.json` внутри `references/` активного навыка. Абсолютные пути, `..`, обратные слеши, символические ссылки и выход за каталог отклоняются.

Некорректный пакет пропускается с безопасным сообщением в `issues` и не останавливает обычный чат. Повреждённое тело может обнаружиться только при активации; тогда навык не загружается. Каталоги `scripts/` не исполняются, `assets/` автоматически не читаются. `SKILL.md` не даёт права запускать shell, Python, браузер, сетевые запросы или устанавливать пакеты. Секреты и рабочие учётные данные в пакетах не хранятся.

### Внутренний API

```python
registry.discover()                       # список описаний, без инструкций
registry.catalog_snapshot()              # {items, issues}, одно сканирование
registry.load_instructions(skill_id)     # инструкции выбранного навыка
registry.read_resource(skill_id, path)   # текст из references/ выбранного навыка
preferences.catalog(user)               # персональный каталог и диагностика
preferences.enabled_skills(user)        # включённые описания с разрешёнными инструментами
preferences.set_enabled(user, skill_id, enabled)  # обновлённый персональный каталог
```

Исходный дескриптор реестра содержит `id`, `name`, `title`, `description`, `allowed_tools`, `metadata`. Он сохраняет объявленные имена инструментов; персональный каталог и исполнитель независимо сужают их до возможностей сервера. Изменение настроек принимает только логическое значение и использует идентификатор текущего аккаунта из серверного контекста.

## Полезные следующие навыки

Эти возможности предложены по существующим модулям, но ещё не установлены как отдельные навыки.

| Предлагаемое название | Основа в проекте | Полезный результат и условие |
|---|---|---|
| Проверка реестра ЗиП | `services/zip_curator/`: словарь, организации и контакты | Проверка обязательных полей, несогласованных наименований и дубликатов в приложенной выгрузке перед загрузкой. Для проверки по актуальному серверному справочнику нужен отдельный разрешённый инструмент чтения. |
| Сравнение показателей воды | `services/water_dashboard/details.py`, `metrics.py` | Сравнение сопоставимых периодов и объяснение рейтинга с указанием источников, пропусков и исключённых противоречивых записей. Не переводить категориальный статус в выдуманный процент. Для произвольных прошлых периодов нужен источник сохранённой истории. |
| Разбор коллективных жалоб | `services/collective/`, `services/appeals/` | Группировка приложенных обращений по теме, территории и периоду с явным правилом объединения; различать количество обращений и охват заявителей. Разбор выгрузки не должен сам менять ручные темы и карточки. |
| Контроль сроков документов | `services/edo/`, `services/overdue/` | Перечень просроченных и приближающихся сроков по приложенному реестру с датой расчёта и ответственными. Актуальный статус из внешней системы требует отдельного доступа; навык не отправляет напоминания. |
| Поручения совещания | Разбор документов и существующий суммаризатор | Решение, исполнитель, срок, источник и вопросы на уточнение из протокола. Для проекта перечня достаточно текущего чтения текста и справочника; для записи поручений нужен новый серверный инструмент. |
| Проверка проекта предписания | `services/cameras/prescription_generator.py` | Контроль комплектности адреса, основания, статуса камеры и выбранного шаблона в предоставленных материалах. Не выдавать текстовый разбор за просмотр видеопотока или фактическую проверку исправности. |
| Проверка муниципального отчёта | `services/municipality_report.py` и сохранённые сводки | Обнаружение несопоставимых дат, неполных источников и противоречий в выводах; сопровождение цифр происхождением. Доступ ограничивается уже разрешёнными сводками. |

Для работы с уже приложенным текстом часто достаточно нового `SKILL.md` и справочника. Точный поиск дублей по большим реестрам, сравнение полных таблиц или новый модульный источник могут потребовать отдельного ограниченного инструмента. Обновление порталов, изменение карточек, отправка сообщений и создание файлов DOCX/XLSX/PPTX не появляются от добавления Markdown-инструкции. Текущие навыки дают ответы и проекты в чате; для старых, неполных и сокращённых локальных материалов прямо указывается ограничение.

## Проверки и поставка

Базовые проверки используют временные каталоги, временную SQLite и подставные ответы модели:

```bash
python -m unittest test.test_skill_registry test.test_skill_runtime
python -m unittest test.test_aichat_skills test.test_aichat_stream_cancel test.test_aichat_uploads test.test_aichat_body_limit
node test/test_aichat_skills_ui.js
```

Проверки реестра покрывают отложенное чтение, появление новых пакетов, некорректный YAML, ограничения путей и персональные переключатели. Проверки исполнителя используют подставную модель и синтетические CSV/XLSX; проверяют арифметику, лимиты, ошибки и запрет недоступных инструментов. Проверки HTTP используют тестовую учётную запись, временную БД и историю, подмену Qwen и отключённый запуск планировщика. Они проверяют каталог, поток, сохранение открытых сведений о действиях, доступ к платформе и совместимость. Проверки интерфейса не требуют браузерного подключения к рабочему серверу.

Для локальной проверки не запускайте производственный `app` с реальными файлами настроек и не используйте рабочие ключи. Контроль нового инструмента должен включать имитационные проверки отказов и попыток расширения доступа. Успешные подставные ответы подтверждают интеграцию, но не качество реального выбора навыков Qwen и не доступность серверного провайдера.

В обычную поставку на сервер входят код, папка `skills/aichat` и зависимость `PyYAML>=6,<7` из `requirements.txt`. Таблица персональных предпочтений создаётся при первом обращении к настройкам; существующие диалоги переписывать не требуется. Рабочие ключи остаются в текущей серверной конфигурации. Для навыков не требуется устанавливать новую внешнюю службу.
