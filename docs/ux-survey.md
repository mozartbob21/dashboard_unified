# Опрос «Оценка удобства и визуального оформления сервиса»

Опрос `service-ux-v1` встроен в FastAPI/Jinja2 и общую SQLite-базу платформы. Дополнительные пакеты и внешние сервисы не требуются. Ответы не отправляются по почте или во внешние API. Идентификатор опроса постоянный: его изменение создаст другой опрос и разрешит повторное участие.

## Пользовательский путь

- Приглашение появляется на главной странице `/` и стартовой странице админ-панели `/users`, после 15 секунд без действий. Вкладка должна быть видима и активна; открытые окна, редактирование формы и ожидающая отправка формы блокируют приглашение.
- Сервер атомарно резервирует показ на 24 часа. Поэтому переходы, перезагрузка, второе устройство и параллельная вкладка не создают повторных приглашений. Счётчик показов увеличивается только после подтверждения фактического открытия окна.
- «Напомнить позже», крестик и Escape откладывают следующий показ на 24 часа от закрытия. Даже при потере соединения действует уже сохранённая серверная отсрочка от момента резервирования показа. Подтверждение показа и откладывание отправляются с `keepalive` и повторяются при сбоях; полностью потерянное подтверждение показа может занизить число увидевших приглашение.
- Анкета доступна по `/feedback/survey`, из меню профиля и из админ-панели. Открытие анкеты также откладывает напоминание, но не завершает участие.
- Черновик сохраняется на сервере через 650 мс после ввода. При конфликте двух вкладок пользователь выбирает свой или более новый сохранённый вариант. При сетевой ошибке введённые данные остаются в форме; доступен повтор и предупреждение перед уходом с несохранёнными изменениями.
- Все шесть оценок обязательны. `0` — отдельный выбранный ответ, `null` — отсутствие ответа. Нет оценок по умолчанию. Комментарий необязателен, максимум 2000 Unicode-символов; более длинный ввод остаётся в форме с объяснением ошибки, но не сохраняется и не отправляется до исправления.
- Администраторы участвуют на общих основаниях. После подтверждённой отправки ответы неизменяемы, черновик очищается, приглашение больше не показывается.

## Доступ и хранение

`routers/ux_survey.py` получает участника из проверенной сессии (`request.state.user`, с резервным чтением cookie через существующий механизм авторизации). Клиент не выбирает участника. Локальный ключ — `local:<id>`, для существующей авторизации Keycloak — отдельное пространство `keycloak:<sub>`.

`ux_survey_state` содержит состояние приглашения и черновик с версией. `ux_survey_responses` содержит только завершённые ответы. Первичный ключ `(account_key, survey_id)`, транзакции `BEGIN IMMEDIATE` и неизменяемость завершённых ответов защищают от дублей, повторных запросов и конкурирующих вкладок. Повторная отправка возвращает успешный результат исходной отправки, не меняя её содержимое или дату.

На уровне API проверяются строгие целые числа 0–5, обязательность полей и длина комментария. В БД также есть ограничения оценок и длины. Комментарии не пишутся в технические логи и выводятся через `textContent`. Ответы API помечены `Cache-Control: no-store`; общая защита запросов платформы от чужого Origin сохранена.

## Аналитика

Раздел **Пользователи и доступ → Обратная связь**, страница `/users/feedback`, API `/api/ux-survey/admin`. Каждый запрос проверяет существующее право управления админ-панелью через `require_account_manager`. Одного названия роли или знания URL недостаточно. Обычным участникам API недоступен.

Периодический запрос выполняется **каждые 10 секунд** в открытой видимой вкладке. Есть тайм-аут запроса, повтор после восстановления сети/возврата во вкладку и время последнего успешного получения данных. Неизменившиеся результаты не перерисовываются. При потере связи остаются последние полученные данные с предупреждением; при 401/403 данные убираются из интерфейса.

Расчёты берут только завершённые анкеты; нули учитываются. Средние показаны с одним десятичным знаком, распределения охватывают все оценки 0–5, у каждого вопроса есть количество ответов. Дни и даты в интерфейсе — московское время. Комментарии без имён, почты и ключей аккаунтов, новые сверху.

Доля завершивших = число завершивших **среди увидевших приглашение** / число увидевших приглашение. Пришедший напрямую из профиля учитывается в общем числе завершений, но не увеличивает эту долю без показа приглашения. Поэтому значение не превышает 100%. При нулевом знаменателе процент не придумывается. Для пустых результатов показано «Пока нет ответов».

## Миграция

`migrations/20261013_ux_survey.sql` применяется автоматически при первой инициализации БД после запуска обновлённой платформы. Повторное применение сохраняет существующие данные. Версия записывается в `app_schema_migrations`.

Явный запуск из корня проекта на Windows, в окружении платформы:

```powershell
.\.venv\Scripts\python.exe scripts\migrate_ux_survey.py
```

Для отдельной проверочной базы:

```powershell
.\.venv\Scripts\python.exe scripts\migrate_ux_survey.py --database C:\Temp\survey-test.sqlite
```

На macOS/Linux аналогичная команда: `.venv/bin/python scripts/migrate_ux_survey.py`.

## Проверки

Автоматические проверки:

```text
python -m pytest test/test_ux_survey.py -q
node --test test/test_ux_survey_frontend.js test/test_ux_survey_admin_frontend.js
```

Серверные тесты используют отдельную SQLite-базу, реальные обработчики опроса и существующую проверку прав админ-панели. Сессионный контекст задаётся тестовым middleware; рабочий сервер и его учётные записи не меняются. Проверяются ноль и отсутствие ответа, строгая валидация, конкурентные отправки/показы/черновики, идемпотентность, 24-часовая отсрочка между клиентами, запрет аналитики участнику, отзыв прав, расчёты, две сессии, комментарии и повторное применение миграции.

Клиентские тесты проверяют сетевые ошибки и повтор, сохранение ввода, Unicode-лимит, доступность оценок, безопасный текст, конфликты вкладок и автоматическое обновление аналитики. В браузере с отдельной тестовой базой проверены полный путь анкеты, восстановление черновика после перезагрузки, нулевая оценка, клавиатура, блокировка неполной анкеты, успешная отправка администратора, появление результата во второй вкладке без перезагрузки, приглашение/Escape, профиль, мобильная ширина и тёмная тема.

Не проверены фактический Windows-сервер организации, реальные мобильные устройства и вход через настоящий Keycloak. 24 часа проверены управляемым временем в тестах, без суточного ожидания. Рабочая база и деплой в рамках разработки не затрагивались.
