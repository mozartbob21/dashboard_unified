# ЕДДС через Chromium-GOST / Chrome на офисном сервере

В этой схеме отчёт получает **офисный компьютер, на котором запущена «Нейрона»**. Пользователи продолжают открывать систему по его IP. На их компьютерах сертификаты портала не нужны.

Python Requests не использует автоматически профиль Chrome, его сетевой стек и выбор клиентского сертификата. Если портал открывается только в Chrome, причина может быть в доверии к УЦ, клиентском сертификате, корпоративных политиках, расширении или настройках сети браузера. Наличие сертификатов само по себе не определяет причину.

## Настройка на сервере

1. Войдите на офисный компьютер **под тем же пользователем Windows**, у которого портал работает в Chrome. Если «Нейрона» запущена службой/планировщиком под другим пользователем, у него может не быть доступа к сертификатам и закрытым ключам. Запускайте процесс приложения под рабочей учётной записью с необходимыми правами.
2. Обновите файлы проекта. Нужный браузер должен быть установлен; Playwright уже есть в requirements.txt. Для Chromium-GOST заранее укажите в `.env` переменные из раздела ниже. Откройте `services\edds\setup_chrome.cmd` из папки проекта. Либо выполните из корня проекта: `.venv\Scripts\python.exe -m services.edds.chrome --setup`.
3. Откроется отдельный рабочий профиль Chrome: `.private/edds/Chromium-Gost-profile`. В нём проверьте вход на `https://zkh-kontur.mosreg.ru/new9/` и открытие отчёта по области. При запросе выберите клиентский сертификат организации. Если нужна установка доверенного УЦ, используйте сертификат, предоставленный вашей ИТ-службой, и проверьте цепочку. Не обходите предупреждение браузера.
4. Если портал открывается в обычном Chrome, но не в этом профиле, сравните применённые политики и необходимые корпоративные расширения. Профиль не копирует личные расширения/настройки. Установленные сертификаты должны быть доступны тому же пользователю ОС. Автоматизация не устанавливает сертификаты и не обходит требования портала.
5. Вернитесь в окно настройки, нажмите Enter — Chrome закроется и освободит профиль. Окно настройки и загрузку из «Нейроны» одновременно запускать нельзя.
6. В `.env` проекта установите `EDDS_ARM_TRANSPORT=chrome`, затем перезапустите «Нейрону». На Windows режим `auto` (по умолчанию) также выбирает Chrome; на других ОС — прежний Requests. В «Пользователи → Логины и пароли» нужен доступ именно «АРМ ЕДДС».
7. Откройте ЕДДС в «Нейроне», выберите неделю и нажмите «Загрузить». Признак успеха — реальные строки отчёта. Сохранённый логин и успешное открытие профиля ещё не означают, что выгрузка проверена.

По умолчанию Chrome запускается без видимого окна. Если портал требует интерактивного выбора клиентского сертификата при каждом запуске, временно установите `EDDS_CHROME_HEADLESS=0` и повторите запрос при открытом рабочем столе сервера. Для полностью фоновой работы ИТ-служба может настроить Chrome AutoSelectCertificateForUrls, строго ограничив правило порталом и нужным сертификатом. Ручной выбор в одном сеансе не гарантирует автоматический выбор в следующем. Для нестандартной установки Chrome доступна переменная `EDDS_CHROME_EXECUTABLE` с путём к исполняемому файлу.

## Chromium-GOST: настройка без переименования кода

В `.env` рядом с `app.py` (не в папке `.venv`) укажите:

```dotenv
EDDS_ARM_TRANSPORT=chrome
EDDS_CHROME_EXECUTABLE=C:/Program Files/Chromium-Gost/chrome.exe
EDDS_CHROME_HEADLESS=0
```

Путь — пример: он должен указывать на установленный EXE Chromium-GOST. `chrome` — внутреннее имя браузерного транспорта; конкретный браузер выбирает `EDDS_CHROME_EXECUTABLE`. Также принимается `chromium-gost` в любом регистре, но для этого значения путь к EXE обязателен. В режиме `auto` на Windows тоже выбирается браузерный транспорт и учитывается указанный EXE.

Имена `services.edds.chrome`, `ChromeArmClient`, `playwright.chromium` и `chromium_sandbox` остаются прежними. Их нельзя заменять на `Chromium-Gost`: это имена Python-модуля, класса и API Playwright, а не название устанавливаемого браузера. Playwright запускает выбранный EXE через параметр `executable_path`, без `channel`.

После изменения конфигурации остановите сервер через Ctrl+C и перезапустите. Если ошибка сохраняется, проверьте, что запускаете нужную копию проекта; установленная переменная среды Windows имеет приоритет над `.env`. Неверный режим возвращается из `/edds/status` как обработанная ошибка 503 с понятным сообщением.

Исправление сохраняет текущий каталог `.private/edds/Chromium-Gost-profile`; файлы профиля, сертификаты и `.env` не входят в пакет обновления. Сборщик жалоб Добродела отдельно использует обычный `playwright.chromium`.

## Как это работает

Загрузка отчётов и вход выполняются через same-origin fetch в вкладке установленного Chrome, включая его TLS-стек. Отчёт возвращается в существующий дашборд; поддержаны основная выгрузка и координаты. Cookies сохраняются в выделенном профиле. Пароль берётся из уже существующего зашифрованного хранилища интеграций. Переадресация запросов с учётными данными на другой сайт запрещена. Проверка HTTPS включена, внешнего отладочного порта нет, профиль не размещается в раздаваемых `static` или `data`.

Не публикуйте `.private` и не включайте рабочий профиль в архив исходников. При смене учётной записи интеграции закройте приложение и удалите только `.private/edds/Chromium-Gost-profile`, затем выполните настройку заново: в старом профиле может оставаться активная сессия прежней учётной записи.

Режим `EDDS_ARM_TRANSPORT=requests` сохраняет прежний способ подключения и поддерживает `EDDS_ARM_CA_BUNDLE`. Автоматического отката на Requests после ошибки Chrome нет: иначе причина несовпадения доступа снова оказалась бы скрыта.

Реальное подключение необходимо проверить именно на офисном компьютере. Сетевые проверки на другом компьютере не доказывают доступность или недоступность портала с офисного сервера.

Официальные источники: [Chrome в Playwright](https://playwright.dev/python/docs/browsers#google-chrome--microsoft-edge), [отдельный профиль для автоматизации](https://developer.chrome.com/blog/remote-debugging-port), [автовыбор клиентского сертификата](https://chromeenterprise.google/policies/#AutoSelectCertificateForUrls).
