# Подготовка СМС и докладов МинЖКХ

Модуль называется **«Дашборд по жалобам МинЖКХ»**. Переход **«Подготовка СМС»**
открывает `/mingkh/sms`. Это часть существующего блока `mingkh`, с теми же правами,
авторизацией, оформлением и учётом посещений. Отдельного сервера из архива не требуется.

## Разделы

- **Сводная СМС** последовательно собирает выбранные блоки в один текст. Частичный
  успех обозначается явно: неуспешный источник не подменяется нулевыми данными.
- **Обращения** — свод за выбранный период и сравнение с аналогичным периодом прошлого
  года, фильтры тематик/источников/ОМСУ и ежедневный доклад.
- **Резонансные** — исходный алгоритм оценки, память найденных адресов, очаги и
  детализация; Excel и CSV для ручного импорта задач в РМ.
- **Системные** — пересчёт по последнему реестру строго раньше выбранной даты,
  последние 30 дней включительно, новые и вернувшиеся улицы, выгрузки.
  Январское окно включает декабрь; показатели за год считаются отдельно. Если в перенесённом архиве есть только реестр на последнюю среду, предлагается сегодняшняя дата пересчёта — она явно показана в поле периода.
- **Решения РМ** — быстрые и системные мероприятия по датам, свод и Excel.

СМС здесь означает подготовленный текст. Приложение не отправляет сообщения и
не создаёт задачи в РМ автоматически. Перед использованием текст и файлы проверяет сотрудник.

## Перенос на рабочий сервер

1. Перенести код обычным способом через GitHub, установить текущие зависимости проекта.
   Нужные библиотеки уже включены в `requirements.txt`; отдельный браузер для этого раздела не нужен.
2. Перезапустить приложение в рамках обычного обновления сервера.
3. Проверить сохранённый доступ **МинЖКХ** в админ-панели. Используется существующий
   `credentials('mingkh')`, портал `https://cur.bi.mosreg.ru`.
4. Для **Решений РМ** используется существующая серверная переменная `MGKH_API_KEY`
   и фиксированный адрес `https://mgkh.rm.mosreg.ru`. При корпоративном центре сертификации
   можно задать `MGKH_CA_BUNDLE`; для МинЖКХ — `MINGKH_CA_BUNDLE`. TLS не отключается.
5. Администратору открыть «Подготовка СМС» → **«Перенос сохранённых реестров»**,
   выбрать исходный ZIP и нажать **«Перенести данные»**. На каждом сервере это нужно
   сделать один раз, поскольку рабочие данные намеренно не передаются через Git.

Импорт читает только `data/omsu.json`, `data/rez_found.json` и
`data/sys_registry/ГГГГ-ММ-ДД.xlsx` внутри ZIP. `.env`, исходный код и остальные файлы
игнорируются без чтения. Архив до 20 МБ. Все поддерживаемые данные проверяются до
записи. Память адресов объединяется; актуальные названия ОМСУ сохраняются.
Повтор одинакового импорта безопасен. Другой реестр на уже существующую дату
отклоняется целиком. При обычной ошибке записи выполняется откат; если сам диск
не позволяет откат, резервные копии и manifest остаются в приватном хранилище
для восстановления администратором.

## Хранение и очередь

Рабочие данные лежат в игнорируемой папке `data/mingkh/sms/`; прямой веб-доступ
к ним запрещён существующим middleware. Файлы не включать в Git. Реестры и память
адресов общие для сотрудников, имеющих доступ к блоку.

Миграция `migrations/20261019_mingkh_sms.sql` автоматически применяется при первом
запуске/опросе расчёта. Она добавляет только таблицу `mingkh_sms_jobs` в существующую
SQLite-базу. При необходимости применить заранее из корня проекта:

```powershell
python -c "from services.mingkh.sms.jobs import initialize; initialize()"
```

Расчёты выполняются последовательно в фоновом потоке. Межпроцессный файловый lock
защищает от одновременного сбора несколькими процессами и конфликта с импортом.
Один и тот же `Idempotency-Key` не создаёт повторную работу. Не более 8 активных
заданий аккаунта и 24 в общей очереди. Клиент опрашивает статус; после обрыва связи
повторное нажатие с теми же параметрами в той же вкладке продолжает ожидание
сохранённого задания. Сетевой повтор не ограничивает длительность самого расчёта.

Результаты задания доступны только создавшему его аккаунту и хранятся 7 дней.
При перезапуске сервера прерванный расчёт получает понятную ошибку, затем можно
запустить его снова. Реестры и память адресов сохраняются независимо от срока задания.
Очередь возобновляется при следующем запросе запуска/статуса; отдельного сервиса очередей нет.

API `/mingkh/sms/api/*` проверяет авторизацию и право `mingkh`; импорт дополнительно
проверяет право управления аккаунтами. Общий middleware приложения проверяет Origin
изменяющих запросов. Данные других пользователей по идентификатору задания недоступны.
Встроенные расчётные страницы `?embed=1` допускают только свой origin; остальные
страницы по-прежнему запрещено встраивать во фреймы. Экспорт CSV защищён от формул,
импорт XLSX не исполняет формулы, макросы или внешние ссылки.

## Проверки

```powershell
python -m pytest -q test/test_mingkh_sms_api.py test/test_mingkh_sms_data.py test/test_mingkh_sms_jobs.py test/test_mingkh_sms_imports.py test/test_sms_system.py test/test_mingkh.py
node --test test/test_mingkh_sms_frontend.js
```

Тесты работают с временными файлами, SQLite и синтетическими источниками; они не
требуют рабочих паролей. Проверка подключения к реальным порталам выполняется
на сервере с настроенными доступами. Подробности фактической проверки интерфейса
и импорта пользовательского архива перечисляются в отчёте о доработке.
